## Proposed scope (to confirm)
### What "current scope" means
The nodes the user can currently see: the accepted snapshot filtered by the active kind filters (and cycle scope/depth, which already shaped the snapshot). Summary describes **visible nodes**, not discovered-but-omitted ones, and says how many are omitted. Selecting a node does not change the summary (optionally highlights its line); Recenter, depth, cycle or filter change does.

### What it contains
Grouped, not per-node walls of text:
1. Headline: seed label/kind + "N nodes, M relationships within D hops (cycle scope)".
2. Composition: counts per node kind (e.g. 4 claims, 3 actors, 2 inferences, 5 sources) and per hop.
3. Key relationships: top few edges by deterministic rank (direct provenance/premise before Related), written as "A -> predicate -> B".
4. Notable nodes: root, highest evidence_count, most-connected (degree), inferences with their premises count.
5. Caveats: omitted nodes/edges, unresolved endpoints, Related = tentative, bounded projection.
Per-node one-liners are available only inside the grouped lists (capped, "+K more"), never for the full set.

### How it is generated
- **Default (deterministic, always on, no model):** built purely from the snapshot in a pure function `scope_summary(snapshot, filters) -> ScopeSummary` (core, unit-testable). Cheap, computed on snapshot accept / filter change, never in draw. This is the "no-model fallback" and is what x3cess sees first.
- **Optional AI narrative (explicit action, not automatic):** a "Summarize scope" button writes a short grouped narrative through the **Summarization role** via the existing `graph_explanation` machinery (same job/log/failure card/cooldown), fed a bounded textual brief of the visible scope. Cached with a `SummaryKey` whose graph revision = hash of the visible node/edge keys (+ memory_changed_seq), focus = seed key; scope change => key changes => cached text shown as "earlier result (stale)" until regenerated. States: idle, writing…, ready, stale, failed (failure card, retry), unavailable (no Summarization route -> deterministic text stays). Reasoning for opt-in: topology promises no model work on open, and models cost/latency.
