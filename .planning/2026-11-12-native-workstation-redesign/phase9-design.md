## Boundaries inspected

- Schema bootstrap applies definitions, migration and schema-v9 checkpoint in one transaction; the shared registry guard serializes new admissions with migration. Field assertions require v2 active registrations and Connect ID equal to workstation ID. The migration changes old registration state/revision and revokes sessions; it does not rewrite `job_origin.origin_json`, `job_request.origin_json`, workstation IDs or installation hashes. Existing migration tests cover active-node mapping/checkpoint/writer rejection; B1 extends previously absent inactive-registration coverage.
- `job_context::record_admission_inner` still checks current registration, scope/access/configuration epochs, workstation identity and exact request-to-job binding. `accepted_request` compares stored scope/deployment/workstation/registration/operation/request identity and preserves legacy JSON via the historical `JobOrigin` decoder. `record_child_in` uses the retained workstation lifecycle fence and copies the original origin; unrelated/system parents remain unattributed.
- `jobs_view::activity_membership/activity_private`, `jobs_paging::predicate/page` and `operational_logs::plan` apply workstation membership/private-origin checks in SQL before row limits, counts/facets and log cohort selection. The removal of child narrowing does not remove scope/deployment/workstation checks. `activity::scope_for_request` explicitly rejects legacy workspace query fields. The review found no additional demonstrated defect in those changed predicates; they still require actual storage checks.
- Cycle deletion uses an exact body fingerprint, mutation context/revision and original `atlas_cycle` request membership. Its own deletion request association cannot satisfy that original-operation check. Tombstone, saved delete receipt and accepted-request association share one transaction. It neither deletes the shared job/evidence/origin nor cancels collection; unknown article counts remain unavailable. Read-only reconciliation explicitly allows `atlas.cycle_history.delete`; B2 repairs the missing post-read authority check.
- Configured maintenance is bounded startup JSON with unique operation, dataset purpose/hash and positive configuration revision. Readiness filters it against the live configuration revision and authorized staged reference. Admission compares configured inputs with the exact request, captures the locked current configuration, and `setup_jobs::admit_in` validates and pins staged bytes in the actual admission transaction. Training remains Natural-only and candidate-only. Accepted requests can be recovered through the read-only receipt path if later configuration no longer permits a new submission.
