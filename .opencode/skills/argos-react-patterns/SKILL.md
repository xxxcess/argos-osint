# Argos React patterns

Use `docs/wiki/code/react-ui.md` for ownership/design and `docs/wiki/code/intel-web.md` for client contracts. Read installed Next docs via `apps/web-desktop/AGENTS.md` before changing app APIs. Paths are relative to the repository root.

- Shared UI uses React Native primitives, `StyleSheet.create` for reusable styles, and `@argos/ui` exports. Keep browser globals/DOM APIs in app code or explicit web adapters; browser persistence and UUIDs use the app-supplied `BackendSettings` adapter. Preserve hydration-safe server/client snapshots; do not initialize persisted state with a synchronous setState effect.
- Keep text in `Text`; use boolean checks or a null-returning ternary when a condition can be `0` or an empty string. Use stable data identity for list keys (articles are run/article occurrences), not indexes when rows can reorder.
- Prefer children/slots and explicit variants over accumulating boolean mode props. Existing orthogonal flags such as disabled/active are valid. Introduce compound context only when related parts actually share state; keep simple primitives simple.
- TanStack Query owns remote data, pagination and mutations in `@argos/api-client`; Context owns backend/preferences/connectivity; component state owns local interaction. Derive display values during render rather than mirroring fetched data into effects/state. Keep mutation triggers in event handlers except the documented once-per-occurrence brief admission.
- Distinguish pending, refreshing, next-page, error and verified empty states; retain readable data during refresh and preserve numeric zero. Use shared loading/empty primitives. Scroll pagination must guard in-flight requests, isolate query keys, deduplicate occurrence identities and retain an explicit retry/load control.
- Preserve backend/instance query namespaces, ready/enabled conditions, opaque cursors, cache reset/invalidation and mutation error/pending behavior. Do not replace Query with SWR or ad-hoc fetch effects. Independent reads should not wait on unrelated requests; honor actual dependencies such as readiness/day selection.
- Keep React Compiler enabled for the Next app and shared transpiled packages. `pnpm lint` registers recommended Hooks/compiler diagnostics and fails on warnings. Keep render pure, hooks unconditional, props/state immutable, refs outside render and effect dependencies complete. Fix diagnostics rather than suppressing them or adding blanket `use no memo` directives.
- Scope subscriptions to the consuming subtree. Let the compiler handle routine memoization; measure slow paths before adding manual memo/useCallback/virtualization. Preserve existing intentional memoization contracts. Extract expensive row work, stabilize identities only where it helps measured rerenders, and consider bounded pagination before a new list library. Inline dynamic styles are acceptable.
- Keep imports statically analyzable and use existing workspace entry points. Lazy-load a genuinely heavy optional feature when justified by bundle evidence; retain a useful fallback and static-export compatibility. Do not add runtime server actions/API routes, native navigation, Expo image/animation packages as incidental optimizations. Changes to compiler/dependency configuration need compatible pins and both export and development browser regressions (`ARGOS_WEB_PROFILE=dev pnpm test:e2e`); never disable it to make a check pass.
- For visual/interaction changes load `argos-react-ui`. Validate with the frontend checks in the design baseline; explain measured performance evidence or compatibility limits rather than claiming an optimization from code shape alone.
- Canvas/graph views need an accessible list twin and tokens passed into draw code; load them lazily client-only and honor reduced motion (see react-ui.md#canvas-visualizations).
