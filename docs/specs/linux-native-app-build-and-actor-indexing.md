# ARGOS_LINUX_NATIVE_APP_BUILD_AND_ACTOR_INDEXING_IMPLEMENTATION_SPEC

Baseline: `xxxcess/argos-osint` · latest fetched `origin/nightly` · `a75d44c7542c2943cfc3e4f465a1bc2c1d7eb77c` · audited 2026-11-14 · clean isolated spec worktree. This PR changes this specification only, not production code.

## Outcome and audit conclusions

Build and open the actual Rune native app on Linux x86_64, pair securely with independently operated Docker Compose services, submit **Build actor index**, follow its durable job through reader-visible completion, and find a seeded actor in Brain. Preserve the concise, responsive native experience and existing macOS behavior.

- **Linux support stops in the application/tooling, not the rendering framework.** `apps/fleetworks-desktop/{Cargo.toml,src/lib.rs,src/main.rs,examples/native_fixture.rs}` gate Rune to macOS; platform/accessibility/Trash adapters import Objective-C; `scripts/fleetworks_platform.py::resolve_native_target` rejects Linux; candidate packaging assumes Mach-O/`.app`. The [pinned Rune manifest](https://github.com/anomalyco/rune/blob/205b8d4f7e60fa6248b83bfbbb4c6a06096c59ff/crates/rune/Cargo.toml) already supplies Vulkan, X11/Wayland, AT-SPI and XDG FileChooser support. Reuse that revision and actual shared views. `metal-backend` has no effect off Apple; do not invent a Rune Vulkan feature or change frameworks.
- **Pairing currently fails closed outside macOS.** `native/keychain.rs::SystemKeychain` returns `Unavailable`; `native/pairing.rs` owns exact-origin secret references and recovery. Add Linux system-keyring storage and explicit session-only mode, never an automatic plaintext fallback.
- **The index pipeline already exists.** `maintenance::admit` requires Native/Operator maintenance authority, current registration and a completed nonempty actor seed inside admission. `setup_jobs` dispatches `actor_reindex`; the worker rebuilds a shadow generation and completes only after promotion acknowledgement. Reuse these boundaries, not a new endpoint or local index.
- **Two client gaps affect this journey.** `GatewayEffects::maintenance` saves `last_request` only after HTTP returns and only in memory. Persist the exact nonsecret attempt before delivery, then reconcile uncertain outcomes. `actor_reindex_job::execute` emits `generation`, `scanned`, `reader_visible`, but `MaintenanceResult` reads `index_generation`, `processed` and omits visibility. Use one typed, backward-compatible result contract.
- **Reuse merged work, do not redo it.** [PR #67](https://github.com/xxxcess/argos-osint/pull/67) merged while this spec was being prepared, at the baseline above, from final head `83a16511a4a727c9650bb9378cb711f08a1985fd`. Its readiness actions, shell/Settings, paging, native-review actor bootstrap, optional local approval, bounded canonical projection, rebuild lease/acknowledgement retry, deduplicated progress writes and simulated-log tests are now baseline. They were initially audited separately at `05ece85c08def8987385185f33ba987a61b1d5ac`; the final delta and merge were rechecked. Preserve these decisions and add Linux support plus the identified client/result gaps. Their reported Mac/backend evidence does not validate Linux desktop behavior.

**Evidence limit:** the available shell is Debian 13.6 x86_64; the separate Linux desktop is Xfce/Xfwm4 at 1364×1024. No Fleetworks app was installed/running. The shell lacked Rust/Cargo, Docker/Compose or Podman, Docker socket, CMake/Clang/Ninja, display variables and relevant window/GPU development packages. No Linux build, pairing, Compose job or live native interaction was run. Repository changes cannot provision those host capabilities implicitly. The UI findings below come from source and inspected, revision-labelled PR #67 synthetic Mac fixtures, not live Linux use.

## Implementation

### 1. Native Linux target and independent backend

- Support `x86_64-unknown-linux-gnu` first, matching this computer. Keep both Darwin targets working; Linux ARM64/Windows packaging is outside this increment. Use Rune's existing Vulkan path, X11 and Wayland input, portal dialogs and AT-SPI. Split platform calls rather than stubbing the production view or returning success without opening a window. Use normal Linux decorations and Ctrl shortcuts instead of emulating Mac traffic lights/Command shortcuts. Propagate Rune `try_run`/window errors rather than claiming a windowless launch succeeded. Honor reduced motion; use a readable matte fallback where transparency/preferences are unavailable.
- Extend the existing `platform --format json` and `build-native --agent --target host --profile debug [--open]` commands. Read-only preflight reports compiler/toolchain, linker/build dependencies, session bus, display, Vulkan loader/adapter and portal availability separately. Missing portal/keyring must not prevent a build; missing runtime prerequisites must produce specific launch diagnostics. Do not auto-install packages, start privileged services, change security settings or report headless rendering as desktop success.
- Package a relocatable review directory/archive with ELF executable, assets, Linux desktop-entry/icon resources, checksum and versioned manifest. Record exact source/Rune revisions, target, profile, toolchain, lockfile digest, dirty state and declared runtime libraries/glibc baseline. Validate ELF architecture, resources and dynamic dependencies using nonexecuting inspection; reject symlinks/path traversal, wrong target and checksum/revision mismatch. Keep Mac `.app`, Mach-O validation and manifests compatible. Default build does not install or launch; `--open` launches only the validated artifact without replacing/stopping an existing app. Report an already-running older revision instead of claiming the new build is active.
- Run services separately through `deploy/native_review.py up --backend-only --name linux-native-index --api-port <unused-port>`, then launch the native candidate and enter the printed gateway origin. Retain the same dedicated project/env/workspace, exact image tags and data on retries. Never mount the Docker socket or give Docker control to the app. Prefer an already configured rootless Docker context where supported; rootless setup is a host prerequisite, not permission to alter the host. Keep loopback-only API publishing, private datastore/search/Jobs ports, read-only mounts, separate purpose tokens and container restrictions.
- An unseeded gateway must show **Seed actors first**. Preserve the existing validated actor CSV upload/configured-input flow and current pinned native-review bootstrap in `compose.actor-bootstrap.yml`; verify the materialized LFS dataset hash and successful nonempty seed receipt before index admission. Keep automatic bootstrap seeding confined to that isolated overlay; generic Compose remains storage-only. Natural training and Atlas model setup are independent and must not gate actor indexing.

### 2. Secure pairing and local persistence

Use the existing `KeychainStore` boundary or a compatibility-preserving neutral name. Keep macOS Keychain behavior and item identities unchanged. Linux persistence uses the user's Secret Service login-session provider, with encrypted provider storage configured by the operator. The [Secret Service API](https://specifications.freedesktop.org/secret-service/latest/ch01.html) does not itself guarantee a provider's at-rest encryption; document the supported provider/configuration and test it. Use only nonsecret exact-match identifiers in [lookup attributes](https://specifications.freedesktop.org/secret-service/latest/lookup-attributes.html), never bearer/polling bytes. Do not use `secret-tool`, a shell command, environment variable, command line, log or JSON file to transport secrets.

- Preserve `(service, installation, canonical origin, secret kind, credential/request ID)` binding, bounded redacted `SecretToken`, protected metadata ownership/modes/no-symlink checks and pending-ID-before-HTTP/promotion recovery. A changed origin/deployment cannot read or send the old secret. Keep `Client`/`PairingClient` proxy/redirect disabling and remote HTTPS/loopback HTTP validation.
- Default to **System keyring**. Missing/locked/denied/unavailable storage is a distinct actionable state. Offer **Unlock keyring / Retry** when applicable and explicit **Use for this session**; never silently downgrade. A user must choose session-only before secrets are retained there. Keep secrets only in the effect-owned, process-local store, clear on disconnect, origin switch, last-window close and Quit, and redact diagnostics. Rune may retain Runtime when a window closes: explicitly disconnect/clear there and require pairing on reopen, not only process exit. Forgetting local secrets does not revoke the server credential; accepted jobs continue. Retain nonsecret installation/attempt metadata, but do not advertise durable reconnect or successful keyring storage. Restart displays **Session ended. Pair again.** Do not create a persistent unlocked/empty-password keyring.
- Persist a versioned nonsecret `credential_storage` discriminator (`system_keyring` or `session_only`) per pairing; missing means existing system-store semantics. Unknown modes fail closed. Session-only metadata is not authority and never falls through to another store. Preserve existing durable pairing during an interrupted session-only replacement; never overwrite it before new approval/authentication. Preserve existing paired Mac records, unresolved pending/promotions and explicit `--api-token-file` mode unchanged. That operator/headless mode remains deliberately separate, with its private-file checks; do not recommend it as GUI fallback.
- Reuse start/poll/operator approval routes, ten-minute challenge, exact issuance replay, Native scope/grants and authenticated registration. The app never receives the Operator token. The merged optional local approval helper remains Mac-gated; Linux may initially use the existing separate operator CLI. If extending that helper for Linux, preserve private local socket, expiry/rate bounds and explicit origin/code comparison plus Approve click; do not add an unauthenticated listener or automatic approval.

### 3. Job, wire and responsive UI contract

**Admission:** `POST /api/v1/search/actors/reindex` sends `MaintenanceRequest { request_id, context }`; no dataset, engine, source label, path or owner assignment. `context` contains `registration_id`, `expected_registration_revision`, `expected_context_revision`, `expected_configuration_revision`. Recheck advertised action, fresh seed readiness, registration and configuration at confirmation; the gateway remains authoritative. `202 MaintenanceReceipt { job_id, operation:"reindex_actors", resource_scope:"backend", origin, dataset:null, reused }` means queued/associated, never completed. Retain all receipt-origin validation and immutable requester associations.

**Uncertain delivery:** add a bounded, versioned nonsecret attempt record through `NativeContainer`'s protected filesystem helpers before POST: canonical origin/deployment/installation, operation, exact request/context and original registration, plus accepted job reference when known. Keep at most one unresolved reindex attempt per origin within the existing bounded metadata budget; refuse additional pending work at capacity, and do not evict unresolved work or automatically POST on startup. Read `GET /api/v1/workstation/requests/detail?operation=actor_reindex&request_id=…&original_registration_id=…` after reconnect/timeout. Unknown stays unresolved. An explicit retry may replay the identical ID/body only under the original valid context; it must never mint a replacement after cancellation, navigation or a lost reply. Show stale-authority errors and an explicit scoped lookup, not cross-origin replay. Reuse the submission reconciliation pattern, not its in-memory-only durability assumption.

**Execution/completion:** retain durable `requested → repairing/starting → scanning → catchup → promoting → completed` phases, active-reader availability, unknown totals, lease epochs, source cursor and exact pending batch identity. Transport/storage interruption or lease loss must replay retained intent under a valid new lease; invalid source/receipt/checksum stays correction-required. Do not clear checkpoints, rebuild from CSV, overwrite canonical actors or treat a scan count/HTTP health probe as readiness. Keep the already-landed suppression of unchanged progress writes without suppressing queue/task heartbeats; do not reimplement the #67 recovery fixes. Share an `ActorReindexResult` in `fleetworks-contracts/src/readiness.rs` using current producer keys: `operation:"actor_reindex"`, `original_job_id`, `generation`, `visible_checkpoint:u64`, `scanned:u64`, `reader_visible:bool`. Decode historical fields deliberately if needed; missing values remain unknown. Job completion requires verified promotion. **Actor search Ready** additionally requires fresh matching source/generation, complete scan, caught-up source/reader checkpoints and no blocked/pressure/recovery condition.

**UI, including observed pain points:** preserve dark graphite/gold styling and existing `ActionButton`, status, dialog and disclosure primitives. [Inspected #67 readiness/Settings/Jobs fixtures at `c4367ffa`](https://github.com/xxxcess/argos-osint/pull/67#issuecomment-6884441649) put the search action below healthy diagnostics and display global Ready alongside incomplete indexing. [Pairing at `2c0ba7b6`](https://github.com/xxxcess/argos-osint/pull/67#issuecomment-6880990486) uses Mac-only copy. These images now describe merged-source design findings, but remain earlier-revision synthetic Mac evidence, not a current-head Linux runtime pass.

- Move the existing **Actor search** summary and **Build actor index** action above expanded healthy checks in Workstation Status; retain a secondary route from maintenance. Show **Connected** for transport, separately **Seed actors first / Not built / Queued / Building / Ready / Paused / Needs attention / Unavailable** for index state. Explain the next action in one sentence. Remove the implied Seed → Train → Index prerequisite; training remains optional.
- Confirmation names the gateway/deployment and shared backend catalog; **Build index** and **Cancel** are the only primary choices. Disable duplicate submission immediately. On receipt show job reference, **Queued** or **Already running**, and **View job** without stealing navigation. Show stage and scanned count, indeterminate progress when total is unknown, last-observed freshness and a bounded details disclosure for generation/checkpoint/recovery reason. Do not invent a percentage or raw worker log stream.
- Keep finite two-second focused active-job polling, one request per lane, stale-response epoch/revision fences and existing 50-row/64-page-history bounds. Refresh readiness once at terminal completion and when its freshness expires while visible; preserve rows/selection during refresh. Pause hidden/unfocused polling, refresh on return, back off failures and never let closing the app cancel accepted jobs. **Search actors** opens Brain after fresh readiness; search remains bounded to 256 UTF-8 bytes, 16 tokens, 25 hits with canonical bulk validation and authoritative dossier reads.
- Setup shows **System keyring** or **This session only**, concise numbered compare/approve instructions, challenge expiry and retry/cancel states. Keep secrets out of views and screenshots. At 1364×1024, 1280×800 and 640×480, keep actions visible: collapse the sidebar to an accessible icon rail at compact width, put detail panes behind selection, wrap explanations, truncate long IDs with accessible full labels, and keep diagnostic content independently scrollable. Preserve keyboard order, visible focus, Enter/Space activation, Escape cancellation and return focus to the triggering control. Do not move focus on poll updates; fix singular/plural job labels in touched views.

## Non-goals and security/performance constraints

No webview/web-app replacement, local engine, Docker/process-control UI, permission expansion, auth/origin bypass, public search service, new generic job API, automatic seed/train/reindex on read, model activation, retired workspace/Trash revival, full shell redesign, release signing/publication, merge or deployment in this spec PR. No macOS security downgrade or automatic credential migration/deletion. Keep server-enforced workstation-only Jobs/logs and canonical source authority; never infer ownership from client IDs.

Preserve existing bounded backend policy: 128-actor source pages; at most 500 mutations/2 MiB per batch; one write in flight; exact saved bodies; persisted pacing/backoff; pressure hysteresis; bounded search and bulk canonical reads, no per-hit N+1 requests. Blocking keyring/filesystem/CSV/packaging work stays off UI/Tokio callbacks with owned cancellation and bounded concurrency. Do not increase limits or memory merely to hide a failure; if realistic fixture evidence requires a resource adjustment, document and test that selected limit independently.
