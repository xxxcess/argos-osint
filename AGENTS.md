# Fleetworks agent orientation

Fleetworks has a Rune macOS API client, an independently operated Linux backend, and the React Native Web desktop. Backend deployment uses direct Docker Compose; Venture, the six terminal clients and legacy `argos` are retired. Six native sidebar destinations share deployment resources or registered activity; the gateway header opens Workstation Status. URL-only setup pairs protected installation identity with origin-bound macOS Keychain access.

Use the [implemented pairing/Keychain flow](docs/wiki/code/native-connections.md#pairing-and-keychain-agreed-target) for normal native setup. Explicit operator/headless token-file mode remains supported; missing Keychain access never falls back to files or unauthenticated access. [Pairing verification](.planning/2026-11-12-native-pairing-implementation/acceptance.md) records pending evidence.

- Start at [docs/index.md](docs/index.md), then the [Fleetworks guide](docs/wiki/code/fleetworks.md) or the relevant concept or code route. Read [contributing](docs/wiki/code/contributing.md) and [conventions](docs/wiki/code/conventions.md) before edits/checks. Preserve unrelated work. `.github` changes belong to Code Architect.
- Follow [scope and finish-line rules](docs/wiki/code/agent-workflow.md#scope-and-finish-line): pin the requested outcome, non-goals and acceptance; review risks early; freeze before final checks. Defer unrelated findings. Late fixes require a demonstrated in-scope blocker and an affected check, not another broad audit. Honor wrap-up immediately.
- Use subagents early when independent work shortens delivery. Assign disjoint paths and concrete outcomes; keep one integration/build owner, wake idle workers explicitly and reuse unaffected evidence. See [execution policy](docs/wiki/code/agent-workflow.md).
- Ask once for verification scope unless already authorized. Read [testing guidance](.opencode/skills/argos-testing/SKILL.md) before tests. Report failures, skips and unverified work honestly; no extra approval gates within existing authorization.
- Before compiling, inspect the existing target/profile/feature cache and reuse the matching debug graph. Rust builds use `python3 scripts/agent_cargo.py … --locked` and shared `target/agents/debug` (or `target/agents/<triple>/debug` for an explicit target); prefer scoped debug checks/tests during iteration. Use release builds only for required packaging, performance or release evidence. Use the scoped Fleetworks checks for the network clients and services. Run the native embedded gate for affected embedded-storage and compatibility paths. Server/all-platform matrices and Rust mutation tests run in hosted CI. Follow [CI](docs/wiki/code/ci.md) and [cache hygiene](docs/wiki/code/contributing.md#build-cache-hygiene). Protect `target/debug`, active builds and global caches.
- Before a full gate, freeze edits, check formatting and budget disk/memory with the build owner. Follow the [resource/graph policy](docs/wiki/code/contributing.md#verification-ownership-and-host-resources); [artifact ownership](docs/wiki/code/build-artifacts.md) distinguishes engine-free native output from embedded backend QA harnesses.
- Pick the narrowest [development loop](docs/wiki/code/contributing.md#development-loops-local-cli-and-docker): host native build and unit tests, then the affected Docker image or web-dev loop, then hosted CI. Docker runs need verification authorization, a dedicated workspace, project name and ports, and never touch the user's running stack or images.
- Multi-phase work uses a concise [named plan](docs/wiki/code/planning-artifacts.md#working-format); separate implementation from verification. Scratch belongs in `.agent-scratch/`, unstaged.
- Update only affected docs/tags/contracts/diagram pairs in the same change. Trace cross-cutting concerns with [tags](docs/wiki/tags.md); follow [wiki maintenance](docs/wiki/maintenance.md).
- Rust changes load `argos-rust-style`. Repository async rules and layout override conflicting upstream platform rules. `cargo fmt` remains the formatter.
- Rune changes load [fleetworks-rune-verify](.opencode/skills/fleetworks-rune-verify/SKILL.md) and follow [native verification](docs/wiki/code/native-verification.md). Use actual views/Runtime and selected PNG/tree/scripts in the shared debug cache; native view-only work does not install or build backend engines. Linux storage/search changes select their own required gates. Native has no Docker/service ownership or topology renderer.
- React work loads `argos-react-ui` and, for components/state/performance, `argos-react-patterns`. Follow [React rules/theme](docs/wiki/code/react-ui.md): terminal-desk structure with matte obsidian/graphite and gold/ivory, shared primitives/tokens, Compiler/Hooks lint, affected fixture screenshots. Topology uses `ForceCanvas` and its list twin.
- Browser verification uses repository Playwright. Set `ARGOS_WEB_TEST_DEV=1` for isolated test output/locks under `.agent-scratch/next-web-tests`; preserve the user's frontend and `.next` locks.
- Follow the current task's authorized verification scope. Injected secret-store tests and Rune Runtime evidence do not establish installed-app or real Keychain behavior. For locked-build or datastore transport failures, use [deployment troubleshooting](deploy/README.md#troubleshooting) before changing dependencies or storage.
- Retired terminal guides and fixtures are [historical evidence](docs/archive/cli-retirement.md). Do not load the historical TUI skill or run retired launcher/terminal commands for new work; use Rune and React workflows for supported clients.
- Host-specific roles apply only when selected: [OpenCode](.opencode/AGENTS.md), [workflow](docs/wiki/code/opencode-v2.md), [Antigravity](.agy/howto.md) ([lite](.agy/lite-team.md), [heavy](.agy/heavy-team.md)).
