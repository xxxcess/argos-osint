# Fleetworks agent orientation

Fleetworks comprises a Rune macOS/Linux x86-64 API client, an Embedded companion, an operator-managed Distributed Linux backend (direct Docker Compose), and the React Native Web desktop. Venture, the six terminal clients, and legacy `argos` are retired. Six native sidebar destinations share deployment resources or registered activity; select the brand avatar for Workstation Status and the sidebar for Settings (`Settings → Connection` switches backends).

## Backends and pairing

- **Distributed & Embedded:** Pair Distributed installations with origin-bound macOS Keychain or Linux D-Bus Secret Service (explicit session-only Linux fallback when unavailable/locked) via the [pairing/Keychain flow](docs/wiki/code/native-connections.md#pairing-and-keychain-agreed-target). Start the bundled companion only via **Start Embedded Backend**. Preserve the [shared backend contract](docs/wiki/code/native-connections.md#backend-types-and-parity). Operator/headless token-file mode remains explicit; missing Keychain access never falls back to files or unauthenticated access ([pairing evidence](https://github.com/xxxcess/argos-osint/blob/15577471cf1e6d0472e918b96ff6868f4834fccf/.planning/2026-11-12-native-pairing-implementation/acceptance.md)).
- **Local macOS review handoff:** `deploy/native_review.py up --approval-handoff` may run the private operator confirmation helper for isolated local review; the operator verifies origin, pairing ID, and code before approving each new pairing (paired Keychain reconnects reuse retained credentials). Never enable in production or pass Operator credentials to the native process ([handoff evidence](https://github.com/xxxcess/argos-osint/blob/15577471cf1e6d0472e918b96ff6868f4834fccf/.planning/2026-11-14-local-native-pairing-approval/acceptance.md)).

## Workflow, scope, and builds

- **Orient & scope:** Start at [docs/index.md](docs/index.md), [Fleetworks guide](docs/wiki/code/fleetworks.md), [contributing](docs/wiki/code/contributing.md), and [conventions](docs/wiki/code/conventions.md). Preserve unrelated work; `.github` belongs to Code Architect. Follow [scope and finish-line rules](docs/wiki/code/agent-workflow.md#scope-and-finish-line): pin outcome, non-goals, acceptance, and intended PR base branch (explicit session branch counts) in a [named plan](docs/wiki/code/planning-artifacts.md#working-format) before changes; freeze before final checks; reopen only for demonstrated in-scope blockers; honor wrap-up immediately. Keep scratch unstaged in `.agent-scratch/`.
- **Parallelism:** Delegate independent work early with disjoint paths, concrete outcomes, one integration/build owner, explicit wakeups, and evidence reuse ([execution policy](docs/wiki/code/agent-workflow.md)). Host roles apply only when selected: [OpenCode](.opencode/AGENTS.md), [workflow](docs/wiki/code/opencode-v2.md), [Antigravity](.agy/howto.md) ([lite](.agy/lite-team.md), [heavy](.agy/heavy-team.md)).
- **Verification & CI:** In [Nightly GSD](.agents/skills/gsd/SKILL.md#github-ci-first), run applicable checks, tests, builds, smoke runs, and captures in GitHub Actions and review exact-head hosted artifacts; run locally only for required local hardware/state with user authorization. Ask once for verification scope unless authorized; read [testing guidance](.opencode/skills/argos-testing/SKILL.md). Offer scoped feature checks + native review, or all applicable gates; confirm local vs. CI. If a passing hosted native artifact matches the user's platform during interactive review, use it while broader gates continue (rebuild locally only when the artifact cannot support the authorized review) and report pending/failing gates separately. Report failures, skips, and unverified work honestly; injected secret-store tests and Rune Runtime do not prove installed-app or real Keychain behavior.
- **Builds & caches:** Inspect and reuse the matching debug graph via `python3 scripts/agent_cargo.py … --locked` and `target/agents/debug` (or `target/agents/<triple>/debug`). Prefer scoped debug checks; reserve release builds for packaging/perf/release evidence. Use scoped Fleetworks checks for clients/services and the native embedded gate for affected embedded-storage/compatibility paths. Server/all-platform matrices and Rust mutation tests run in hosted CI only. Freeze edits, format (`cargo fmt`), and budget disk/memory before full gates; follow [CI](docs/wiki/code/ci.md), [cache hygiene](docs/wiki/code/contributing.md#build-cache-hygiene), [resource/graph policy](docs/wiki/code/contributing.md#verification-ownership-and-host-resources), and [artifact ownership](docs/wiki/code/build-artifacts.md). Protect `target/debug`, active builds, and global caches.
- **Dev loops, code & docs:** Pick the narrowest [development loop](docs/wiki/code/contributing.md#development-loops-local-cli-and-docker); Docker requires authorization, dedicated workspace/project/ports, and never touches the user's stack/images. Rust loads `argos-rust-style` (repo async/layout rules win). Troubleshoot locked builds or datastore transport via [deployment troubleshooting](deploy/README.md#troubleshooting) before changing deps/storage. Update only affected docs, [tags](docs/wiki/tags.md), contracts, and diagram pairs ([wiki maintenance](docs/wiki/maintenance.md)). Retired terminal docs/fixtures are [historical evidence](docs/archive/cli-retirement.md); never load the TUI skill or run retired commands.

## UI changes

- **Native Rune:** Load [fleetworks-rune-verify](.opencode/skills/fleetworks-rune-verify/SKILL.md). Exercise production views with synthetic Runtime tests, inspect generated PNGs and accessibility trees before visual sign-off, and track the exact-head Linux package.
- **React Native Web:** Load [argos-react-ui](.opencode/skills/argos-react-ui/SKILL.md) (plus `argos-react-patterns` for APIs/state/perf). Preserve Intel Web routes and the topology/list pair; run compiler and Playwright checks and inspect Playwright screenshots before visual sign-off.
- **Theme & Nightly GSD tracks:** Both clients follow [Glass Canvas](docs/design/matte-canvas/theme.md) (`#060709` backdrop, layered smoked/frosted glass, static liquid-metal rims, molten-gold/cyan accents, fractured crescent textures, opaque fallbacks) and the [interaction-state contract](docs/design/matte-canvas/interaction-state.md). In [Nightly GSD](.agents/skills/gsd/SKILL.md#nightly-workflow-canonical), pass one runs affected Linux x86-64 native/backend CI; once green, dispatch macOS and Web checks for the same SHA. **GSD Nightly Core** resolves comments and pushes verified fixes; **GSD Nightly UI** posts visual review feedback on open `nightly` PRs; **nightly performance security** ([GSD track](.agents/skills/gsd/SKILL.md#nightly-performance-security), [standards](docs/wiki/code/performance-security-scalability.md)) reviews exact-head performance, scalability, and security regressions.
