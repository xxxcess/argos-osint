## Outcome and audited decisions

Build **one visual system, two distinct products**. Native is the workstation operations desk; Intel Web is a minimal Brain evidence portal. This is the implementation contract. The reference video is not required to execute it; the observed patterns and Fleetworks-specific decisions are recorded below.

| | Native workstation | Intel Web |
|---|---|---|
| Center | Current Fleetworks operations and Jobs & Logs | Home, Bulletin, Brief, actors, recorded topology |
| Navigation | One collapsible sidebar; Settings stays | Compact header and restored bottom nav; no left sidebar or Settings |
| Utilities | Right Assistant, Inbox popover, local command panel | No Assistant, chat, Inbox, command palette, or top-right toggle |
| Discovery | Existing actor search; command filters known actions only | One article title/description search on the existing full-text index |
| Startup | Quiet Orbit splash (3 s) → explicit Local Embedded / Remote Gateway | Existing registered Connect ID gate; no splash |
| Brand | Logo only, including startup and navigation | Logo only, including Connect and header; backend name in the Home control is a functional label |

**Audit:** Rune already has adaptive layout, a read-only context rail, material recipes and scoped Jobs/Logs but no Assistant, Inbox, command panel or splash. The web already has a reusable bottom status bar and contextual Brief activity; it is not an operational Jobs/Logs dashboard. The current Home label derives from host OS; the service display name requires a distinct backend projection. SurrealDB already maintains separate article title and description BM25 indexes; the browser uses broader feed search and does not allowlist the indexed endpoint.

## Addendum: Quiet Orbit, matte theme and stable live states

Posted by the repository owner on this PR. Where it conflicts with the sections below (the old static JPG, reflective controls, ivory primary highlights, page-button lists), the addendum wins.

1. **Native splash and logo.** The selected Quiet Orbit: a slowly turning dim ivory molten-glass core, an obsidian crescent with sparse faint flecks, and five opaque obsidian-glass triangular satellites. No satellite may touch the crescent at any phase. The eight-second preview is the motion reference; the native startup plays its first part at the same pace over three seconds, then crossfades into gateway selection, composited over `#060709` with no media rectangle. The whole orbital envelope scales at compact widths, fractional scale and high DPI. Reduced Motion and asset failure show a matching static symbol. Gateway selection and **Start Local Backend** / **Connect** stay separate; the splash starts and reconnects nothing. Native only; Intel Web shares the visual language.
2. **Shared matte theme.** Uninterrupted dark canvas, charcoal tonal steps, hierarchy by spacing and weight, cool gray text. Metallic sheen only on the main logo; a restrained cool shimmer only while loading. Fractured-obsidian texture only on Submit, Confirm, Create, Delete and Connect. Status colors (cyan live, blue info, mint healthy, amber warning, rose error, violet queued, slate unknown) always pair with a label or icon. Responsive grids for dense overview, options and readiness screens; tables where comparison matters.
3. **Real-time state and scrolling.** Separate initial loading, refresh, pending action, stale or error, and completion. Layout-matched skeletons only for unresolved regions. Resolved content stays visible on refresh; same-scope data survives a transient failure with a recovery control and never survives a backend or scope switch; an outdated response never overwrites newer state. Jobs & Logs uses continuous, bounded cursor loading instead of Previous/Next.

Verify on Linux x86-64 first: cold startup through gateway and service screens, full-orbit clearance and scale, Reduced Motion, compact layout, and Jobs scrolling and selection over append, refresh and failure. Typed local CSV stays the primary Linux import path.

The canonical theme, state and Quiet Orbit reproduction docs live in the matte canvas design reference (`docs/design/matte-canvas/README.md`, added by PR 70). This spec only records the decisions.

## Implementation phases

### 1. Shared production component catalog

- **Superseded by the [addendum](#addendum-quiet-orbit-matte-theme-and-stable-live-states).** Use the tokens in the matte canvas theme (`docs/design/matte-canvas/theme.md`, PR 70): canvas `#060709`, cool group bodies and text, cyan interactive accent and flat semantic colors. Keep ~8-unit rhythm, 20–24 page gutters, and monospace only where it aids scanning. Reading panels stay opaque.
- Buttons, tiles, segmented controls, fields, overlays and the composer are flat and matte: no reflective finish, glow, drop shadow or pointer lighting. Only real Submit, Confirm, Create, Delete and Connect actions carry the fractured-obsidian texture. The composer and the command overlay may keep a same-window blur with an opaque fallback; Linux does not need a blanket matte fallback for that. Web uses the same tokens with an opaque fallback.
- Rebuild the catalog from production components in Rune fixtures and web visual tests: navigation/status, buttons/fields, tiles, job cards, disclosure, evidence context and native-only overlays/composer/splash. Cover default, hover, keyboard focus, pressed, selected, busy, disabled and reduced preference states. No second component system or public catalog route.

### 2. Native startup, operations and utilities

- Play the **Quiet Orbit** scene (vector, `orbit.rs`) over the shared `#060709` canvas with no wordmark. Time from first visible frame: full scene from the first frame to 2.65 s, crossfade into **Choose your connection** until 3 s. Reduced Motion shows one complete still for the same 3 s. Run once per cold launch, not on reconnect. The splash starts no backend and reconnects nothing. Keep protected profile/pairing recovery, but gate auto-reconnect behind explicit selection and action this launch. **Local Embedded** uses existing Start/Stop and IPC readiness; **Remote Gateway** uses URL, operator pairing, keyring/session mode and registration. Do not silently start a companion or fall back to HTTP.
- Preserve actual platform chrome, ~44 pt toolbar, existing ~220 pt ops rail (52 pt compact) and one active center view. Dock the ~380 pt Assistant when space permits; overlay it if center width would drop below ~640 pt. Keep context information with the relevant operation, not a second permanent rail. Recompose authorized screens using shared primitives and permission/freshness states. Do not remove the Linux typed CSV fallback, retry or setup recovery.
- **Jobs & Logs:** ~300 pt list plus detail when space permits; otherwise list → detail with Back. The list loads continuously through a bounded cursor (one **Load more** control, no Previous/Next or page numbers); rows, selection and scroll stay on refresh and fetch. Show phase and progress before receipt, reader visibility and timestamped safe logs; unknown totals stay indeterminate. Preserve View job, job polling vs log recovery, scope/staleness, and eligible retry confirmation. No raw logs, bulk actions, cancel or global logs.
- **Inbox:** native bell popover, All/Unread and expandable list/detail. Use allowlisted already-observed job/readiness/connection transitions; dedupe by scoped event/job+transition, cap retention, reset at authority change. No notification service, push, secrets or device-wide alert claim. **Command:** native button and Cmd/Ctrl+K; grouped typed navigation/actions, arrows/Enter/Escape, restored focus. Destructive/accepted-work actions only open their existing review. One overlay owner; no arbitrary command runner.

### 3. Native contextual Assistant

Use a pinned actor/job/cycle/readiness context, bounded in-pane history, scroll anchor and a multiline glass composer. Enter sends, Shift+Enter inserts a line, IME never submits. Keep drafts within the same authorized context; switching context is explicit. Collapsing does not submit or cancel.

Add a capability-gated typed chat contract over HTTP **and** IPC, with workstation-owned threads, bounded message/event pages, actual queued/running/retry/final states and safe source citations. Resolve evidence authorization server-side, never from client-supplied evidence. Reuse captured admission, durable job/outbox and lease/reconciliation owners; exactly one accepted message/turn on replay, no new ID on timeout/EOF, no stale writes after authority changes. Advertise unsupported/unavailable separately from permissions and configuration. V1 is status then final; no fake streaming, autonomous tool execution or automatic publication. Keep sending gated until real endpoints and both transports pass. Proposed fixed routes under `/api/v1/workstation/chat/`: POST `turns` and GET `threads`, `messages`, `events`, with typed SDK/IPC equivalents. Reads require `ReadWorkstationActivity + Registered`; submit requires `SubmitInteractive + Registered`. Turn input carries durable request ID, mutation context, optional thread ID, expected thread revision and typed source reference. Receipt returns thread/turn/message/job/request IDs, revision and queued state. Bounds: 4 KiB input, 64 KiB captured evidence, 32 KiB final answer, 50 messages/page, 100 events/page with at most 4 s wait, and 256 KiB/page. Query authorized evidence in bounded batches; no N+1 or unbounded polling.

Revalidate current authority, reconcile the original durable request **before** revision/active-turn checks, then atomically admit one turn, message, job and outbox entry. Existing request with changed immutable inputs conflicts. Persist recovery before submit; use bounded resumable events, queue leases and exact-once final application. Keep chat out of routine diagnostics, browser relay, and provider credentials out of the client.

### 4. Minimal Intel Web and indexed discovery

- Use logo-only header with **Search articles and actors…**, no utility cluster. Keep evidence central, a ~300–360 px sources/related/provenance column where useful, and stack it on narrow screens. Retain Home/Bulletin/Brief/Actor/Topology history and exact occurrence routing, and `ForceCanvas` with its accessible list. Refactor current 75% global scale and graph inverse zoom together. Reserve footer height and safe area; no obstruction of content/keyboard.
- Restore `IntelStatusBar`: **backend display name → Home**, Bulletin and contextual Jobs; **Backend host** CPU/Memory/Disk plus connection state. Host readings use `useHostMetrics`; unavailable is — and zero remains 0. Project optional `platform_identity { deployment_id, display_name }` from authorized readiness, configured through proposed bootstrap-only `--platform-display-name` using existing deployment metadata; absent input preserves the value. Bound the display name to 64 printable characters/256 UTF-8 bytes and reject blank/control-character input. Fallback **Backend**; do not derive from OS, chipset, hostname, IP or Connect ID. Scope/cache it separately from metrics, preserve deployment ID on rename, and clear on backend change.
- Wire explicit-submit `GET /api/v1/articles/search` through the same-origin relay and a typed query hook. Preserve registered session and reset/access fences, add the corresponding typed IPC read to match capability, keep default browsing when query is cleared. Match only indexed title/description; keep title-first BM25 ranking, bounded pages and opaque cursor tied to query/filters/scope/result-window revision. Preserve exact `run_id/article_id` and search state on Back. Distinguish no hits, refresh, error, stale page and unavailable index. Let existing database publication, deletion and retention maintain the index; no duplicate engine or worker. Bootstrap owns index repair; never run schema writes or background jobs from search. Limit plain query to 256 UTF-8 bytes and 16 distinct terms, default 20 results/max 50, and surface truncation when the bounded candidate window is exhausted. Optional source/date/domain filters narrow results but are not full-text fields. Gate on indexed-route availability, not an empty corpus; retain no last-backend results across a scope change.

### 5. Documentation and release evidence

Update root/app READMEs and `docs/wiki/code/{fleetworks,native-design-system,native-connections,native-verification,intel-web,react-ui,architecture,storage}.md` where behavior changed; update paired HTML/SVG diagrams `native-workstation-layout`, `native-connections` and `workstation-readiness` for changed flows. Add article-search and Assistant contract docs; update the development-only component inventories alongside them. Replace conflicting old allowlists; preserve historical evidence labels. This PR starts spec-only. Do not add unrelated dependencies, migrate frameworks/storage, or publish/deploy as part of its handoff.
